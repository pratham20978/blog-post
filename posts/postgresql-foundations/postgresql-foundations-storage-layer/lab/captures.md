## 0. A checkpoint before anything else

The first change to a page after a checkpoint carries a full-page image (part 1). Taking one now, before the load, means every page the load creates is born after it — so the two updates in steps 3 and 4 log only their own changes.

### Does column order change the page count?

Same million rows, with the 8-byte `created` column moved first so no padding is needed before it. CREATE TABLE AS inserts in bulk, and 16 extends a relation several pages at a time for bulk inserts, so the last few pages may be allocated but never initialised.

```sql
create table orders_packed as
select created, id, customer_id, amount_cents, status from orders;
select pg_relation_size('orders_packed') / 8192 as pages_packed,
       pg_relation_size('orders') / 8192 as pages_original;
select count(*) filter (where lower > 24) as pages_with_rows,
       count(*) filter (where lower = 0)  as never_initialised,
       max((lower - 24) / 4)              as most_rows_on_a_page
from generate_series(0, pg_relation_size('orders_packed') / 8192 - 1) b,
     page_header(get_raw_page('orders_packed', b::int));
```

```text

--------------+----------------
         7360 |           7693
(1 row)

-----------------+-------------------+---------------------

(1 row)
```
