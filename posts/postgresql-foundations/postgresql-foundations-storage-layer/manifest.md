# Upload manifest — postgresql-foundations-storage-layer

Every placeholder in `blog.md`, in order of appearance. Upload each file to the public MinIO
`media` bucket under its suggested object key. The public URLs then follow the pattern
`https://minio.canery.in/media/<key>`. `urls.txt` is pre-filled **in this row order** from those keys; edit it if any upload lands under a different key, then run:

```bash
python3 .claude/blog-forge/scripts/fill_urls.py posts/postgresql-foundations/postgresql-foundations-storage-layer/ posts/postgresql-foundations/postgresql-foundations-storage-layer/urls.txt
python3 .claude/blog-forge/scripts/validate_post.py posts/postgresql-foundations/postgresql-foundations-storage-layer/ --publish
```

`COVER` sits in the frontmatter key `cover_image_url`, not in the body. The Canery contract rejects
a non-URL there, so it must be resolved before upload. Object keys carry the post slug as a suffix
so they cannot collide with parts 1 and 2 in the same flat bucket; the suffixed copies already
exist in `assets/`. Set `Content-Disposition: attachment` on the four lab files if the upload tool
allows it.

Every figure went through the route gate in `blog-visuals/references/visual-taxonomy.md`. No
paper figure is reused (see the ledger's figure candidates), so no row is routed `source`. 21
figures are ours, hand-placed or charted from `lab/captures.json`, and keep their `.html` source.
FIG_20 is routed `mermaid`: its source is `assets/fig-20-crash-replay.mmd`, rendered by
`assets/_fig20.py` (mermaid-cli, then the same headless-Chrome shim, with absolute paths).

## Rebuilding the figures

```bash
cd posts/postgresql-foundations/postgresql-foundations-storage-layer/assets
python3 _figs_a.py          # FIG_01–FIG_11, numbers read from ../lab/captures.json
python3 _figs_b.py          # FIG_12–FIG_22 except 20
python3 _fig20.py           # FIG_20 via mermaid-cli (needs npx and /usr/bin/google-chrome)
python3 _cover.py           # the cover
```

After any rebuild, copy each `fig-NN-*.png` to its `-postgresql-foundations-storage-layer.png` twin before uploading, bump the
key to a new version if the old one was already published, and open every PNG.
